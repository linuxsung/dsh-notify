## 1. GIT FLAG — 체크포인트 규약

**원칙: 모든 작업은 커밋된 기준점 위에서 시작하고, 검증을 통과한 지점마다 커밋으로 못 박는다.**

### 1.1 세 지점

| 지점 | 시점 | 명령 | 통과 조건 |
|---|---|---|---|
| **START** | 작업 시작 직전 | `git status --short --branch` → `git log -1 --format='%h %s'` | 트리가 깨끗하고 기준 커밋 해시를 확인했다 |
| **STEP** | 한 단계의 검증(테스트 실행) 통과 직후 | `git add <이 단계 파일>` → `git commit` | 그 단계 테스트가 실제로 초록이었다. 실패 상태 커밋 금지 |
| **END** | 작업 종료 시 | `git status` → `git log --oneline -n <세션 커밋 수>` | 트리가 깨끗하고, HEAD 해시를 사용자에게 보고했다 |

START 에서 트리가 더러우면 **새 작업을 시작하지 않고** 먼저 기준 커밋을 만든다. END 에서 더러운 파일이 남아 있으면 작업은 미완료다.

### 1.2 커밋 메시지

```
<type>(<scope>): <한 줄 요약>

왜: <이 변경이 필요한 이유>
검증: <실행한 명령>
결과: <통과/실패 수치>
```

- `type` ∈ `docs` `test` `feat` `fix` `chore`
- `scope` ∈ `protocol` `tests` `peak` `holiday` `provider` `repo`
- 한 커밋에 관련 없는 파일을 섞지 않는다. 히스토리를 재작성하지 않는다.

### 1.3 마일스톤 태그

마일스톤 커밋에는 주석 태그를 붙인다.

```powershell
git tag -a milestone-2 -m "판정 코어 초록불"
git tag --list 'milestone-*'
```

헤더의 `git:` 필드는 완료된 마일스톤 **태그명**을 적는다. 커밋 해시를 제 자기 자신의 내용에 적는 것은 불가능하므로(자기 참조) 해시 대신 태그를 쓴다. 현재 HEAD 해시는 `git log -1 --format=%H` 로 언제든 확인한다.

### 1.4 금지

- 실패하는 테스트를 포함한 커밋
- `git add -A` 로 무관한 파일 묶기
- 커밋 없이 여러 단계를 진행한 뒤 한 번에 커밋
- 강제 푸시·히스토리 재작성

## 2. 헤더 + 스켈레톤 인덱스

> **순서 규칙 — 파일을 쓰기 전에 헤더와 인덱스(뼈대)를 먼저 만든다. 그 다음에 내용을 채운다.**

이유: 헤더가 목적·계약·검증 방법을 먼저 고정하면 본문이 그 목적에서 벗어나지 않고, 인덱스가 있으면 읽는 사람이 본문을 전부 읽지 않아도 구조를 파악할 수 있다.

### 2.1 문서(`.md`) 헤더

제목 바로 아래에 blockquote 1줄:

```markdown
> 상태: active · 최종 갱신: YYYY-MM-DD · git: main @ milestone-N · 상위: <상대 링크>
```

- `상태` ∈ `draft` `active` `frozen`
- 상위 문서가 없으면 `상위: -`

이어서 `## 인덱스` 표:

```markdown
## 인덱스

| § | 섹션 | 이동 | 한 줄 요약 |
|---|---|---|---|
| 1 | 요금 규칙 | [§1](#1-요금-규칙) | 피크 창과 오프피크 비율 |
```

- **섹션을 추가·삭제·순서 변경하면 같은 커밋에서 인덱스를 갱신한다.**
- 표는 본문과 같은 순서로 둔다.

### 2.2 개발 파일(`.ps1`) 헤더

comment-based help 로 통일한다.

```powershell
<#
.SYNOPSIS    한 줄 목적
.DESCRIPTION 동작 요약
.CONTRACT    준수하는 계약 위치 (예: docs\2026-10-20-dsh-notify-design.md §2.2)
.INPUTS      파라미터 의미
.OUTPUTS     반환 객체 형태
.SIDE-EFFECTS 네트워크/캐시 쓰기 여부
.TESTS       대응 테스트 파일과 케이스 번호
.NOTES       스펙 문서 절 참조
#>

#region INDEX
#   Symbol             목적                          대응 테스트
#   Get-PeakDecision   과금 구간 판정                tests\peak-decisions.ps1 #1-9
#endregion
```

- 코드 인덱스에는 **숫자 줄번호를 쓰지 않는다** — 코드가 움직이면 숫자가 거짓말을 한다. 심볼명·목적·테스트 케이스로 색인한다.
- 새 심볼을 추가하면 `#region INDEX` 도 같은 커밋에서 갱신한다.
- `Set-StrictMode` / `$ErrorActionPreference` 는 테스트 스크립트에만 적용한다(provider 는 상위 로더가 실패를 격리해야 하므로 스스로 던지지 않는다).

## 3. 자동 검사

`tests\docs-contract.ps1` 이 저장소 전체를 훑어 아래를 검사한다.

| 대상 | 검사 |
|---|---|
| `README.md`, `docs\*.md` | 제목 다음 8줄 안에 `> 상태:` 헤더 줄, 그리고 `## 인덱스` 절 |
| `providers\*.ps1`, `tests\*.ps1` | `<#` 블록 안 `.SYNOPSIS`, 그리고 `#region INDEX` |
| 그 외 | 검사 대상 아님 (`.gitkeep`, `cache\`, `config.json`) |

위반이 있으면 파일과 사유를 출력하고 종료코드 1. 전체 테스트는 `tests\run-all.ps1` 로 돌린다.

## 4. 새 파일 체크리스트

1. 이 문서의 템플릿으로 **헤더**를 쓴다
2. 섹션/심볼 목록으로 **인덱스(빈 뼈대)** 를 쓴다
3. 본문 또는 구현을 채운다
4. 인덱스와 실제 구조가 일치하는지 확인한다
5. `tests\run-all.ps1` 초록 확인 후 STEP 커밋
